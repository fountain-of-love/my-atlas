# Specifications

Specifications describe the expected shape of a kind of model entry. They are contracts for useful questions and interoperable structure, not bureaucratic forms.

Different domains may need different specifications. A project, skill, person, and experience should not be forced into one universal schema.

Start with the smallest structure that makes an entry useful to both a human reader and a machine. Revise the spec when real entries expose a recurring need.
