# Project specification

A project entry should describe created work without reducing it to a title or technology list.

## Optional metadata shape

```yaml
type: project
status: ""
organization: "[[Organization]]"
domains: []
skills: []
experiences: []
outcomes: []
evidence: []
```

The fields are a starting point, not a required universal schema.

## Identity

- What is the project called?
- What period, domain, or organization does it belong to?

## Intent and context

- Why did it exist?
- What problem, opportunity, or question shaped it?

## Contribution

- What did Yves create, decide, lead, or change?

## Form

- What was produced?
- Which concepts, skills, technologies, or collaborations were involved?

## Outcome and evidence

- What changed as a result?
- Which artefacts, repositories, releases, metrics, talks, or references support the account?

## Learning

- What did the project reveal?
- What patterns or practices should carry forward?
